## 3️⃣ Сравнительная таблица PMBoK vs SCRUM

| Критерий | PMBoK | SCRUM |
|----------|-------|-------|
| **Подход** | Предиктивный (plan-driven) | Адаптивный (agile) |
| **Планирование** | Детальное на старте | Итеративное (каждый спринт) |
| **Изменения** | Через Change Control | Приветствуются |
| **Документация** | Обширная | Минимальная |
| **Роли** | PM, спонсор, команда | PO, SM, Dev Team |
| **Фазы/Итерации** | Последовательные фазы | Спринты 2-4 недели |

## 4️⃣ Схема жизненного цикла типового проекта

**Универсальный ЖЦ любого проекта:**

```
[Инициация] → [Планирование] → [Исполнение] → [Завершение]
                     ↑__________________|
                    (Мониторинг и контроль)
```

Фазы:
1. **Инициация:** Определение целей, устав проекта
2. **Планирование:** WBS, график, бюджет, риски
3. **Исполнение:** Выполнение работ
4. **Мониторинг:** Контроль отклонений
5. **Завершение:** Приёмка, закрытие

## 6️⃣ Сравнение двух ЖЦ и выводы

| Аспект | Типовой ЖЦ проекта | ЖЦ программного проекта |
|--------|-------------------|------------------------|
| **Продукт** | Любой (здание, событие) | Программное обеспечение |
| **Инкременты** | Обычно один результат | Частые релизы (MVP → v1 → v2) |
| **Обратная связь** | В конце фаз | Непрерывная (CI/CD) |
| **Изменения** | Дорогие | Относительно дешёвые |
| **Тестирование** | Финальная приёмка | Continuous testing |

**Выводы для записи:**
1. Программные проекты более гибкие благодаря природе ПО (можно быстро изменить код).
2. Итеративный подход снижает риски — ошибки выявляются раньше.
3. Для FlowGuard подходит итеративная модель: сначала парсер PCAP, потом признаки, потом ML.
