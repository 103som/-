## 📝 РАЗДЕЛ 2: Описание продукта

### 2.1 Назначение продукта

> **FlowGuard** — это консольная система для оффлайн-анализа сетевого трафика на предмет аномалий.
>
> Система решает проблему: традиционные методы глубокой инспекции (DPI) не работают на зашифрованном TLS-трафике. FlowGuard анализирует метаданные соединений (JA4-фингерпринты) и поведенческие признаки потоков, применяя алгоритм Isolation Forest для выявления аномалий без расшифровки.
>
> **Ключевые возможности:**
> - Приём PCAP-файлов через CLI
> - Извлечение JA4-фингерпринтов из TLS ClientHello
> - Формирование flow-признаков (статистика потоков)
> - Детектирование аномалий алгоритмом Isolation Forest
> - Формирование отчёта с anomaly_score и интерпретацией

### 2.2 Целевая аудитория

- Исследователи в области информационной безопасности
- Аналитики SOC-центров
- Специалисты по Threat Hunting
- Студенты, изучающие сетевую безопасность

## 📝 РАЗДЕЛ 3: Границы проекта

### 3.1 Что ВХОДИТ в проект (In Scope)

| ID | Элемент | Описание |
|----|---------|----------|
| S-01 | Парсер PCAP | Чтение PCAP-файлов на C++ с извлечением метаданных |
| S-02 | Извлечение логов | Формирование conn.log, tls.log, ja4.log |
| S-03 | Flow-признаки | Агрегация пакетов в потоки, расчёт статистик |
| S-04 | JA4-фингерпринты | Извлечение JA4 из TLS ClientHello |
| S-05 | Объединение данных | Связывание flow + JA4 в единую структуру |
| S-06 | ML-детектор | Isolation Forest для обнаружения аномалий |
| S-07 | Anomaly scoring | Расчёт оценки аномальности ∈ [0;1] |
| S-08 | Классификация | Преобразование score в LOW/MEDIUM/HIGH/CRITICAL |
| S-09 | CSV-отчёт | Экспорт результатов в CSV |
| S-10 | JSON-отчёт | Экспорт результатов в JSON |
| S-11 | Интерпретация | Указание 1-2 ключевых признаков решения |
| S-12 | CLI | Командная строка для запуска |
| S-13 | Docker-образ | Dockerfile для развёртывания |
| S-14 | Документация | README, ПЗ, РО, ПМИ по ГОСТ |

### 3.2 Что НЕ ВХОДИТ в проект (Out of Scope)

| ID | Элемент | Причина исключения |
|----|---------|-------------------|
| OS-01 | Real-time анализ | Только оффлайн-обработка PCAP, требует архитектурных изменений |
| OS-02 | Графический интерфейс (GUI) | CLI достаточно для целевой аудитории |
| OS-03 | Веб-интерфейс | Требует отдельного проекта на JS |
| OS-04 | Интеграция с SIEM | Требует изучения API конкретных SIEM |
| OS-05 | IPS-функционал | Система только детектирует, не блокирует |
| OS-06 | Расшифровка TLS | Анализ только метаданных, без MITM |
| OS-07 | Поддержка Windows | Только Linux/POSIX, упрощает разработку |
| OS-08 | QUIC/HTTP3 | JA4 для QUIC в разработке, не стабилен |

## 📝 РАЗДЕЛ 5: Ограничения и допущения

### 5.1 Ограничения (Constraints)

| ID | Ограничение | Влияние |
|----|-------------|---------|
| C-01 | Срок — защита ВКР (июнь 2026) | Жёсткий дедлайн |
| C-02 | Бюджет = 0 (учебный проект) | Только бесплатные инструменты |

## 📝 РАЗДЕЛ 8: Подход к управлению рисками

> Полный реестр рисков — см. **Temp4 – RiskRegister.xlsx**

### Верхнеуровневые риски:

| Риск | Уровень | Стратегия |
|------|---------|-----------|
| RK-01: Недоступность датасетов | Средний | Смягчить (заранее скачать) |
| RK-02: Некорректные PCAP | Средний | Смягчить (валидация) |
| RK-03: Неподдерживаемые TLS | Низкий | Принять (flow-only режим) |
| RK-04: Переобучение ML | Средний | Смягчить (кросс-валидация) |
| RK-05: Медленный парсер | Низкий | Смягчить (профилирование) |
| RK-06: Проблемы Docker | Низкий | Смягчить (CI/CD) |
| RK-07: Изменение требований | Средний | Смягчить (резерв времени) |
| RK-08: Потеря кода | Низкий | Избежать (Git + GitHub) |

### Процедура управления рисками:

1. **Идентификация:** При обнаружении нового риска — добавить в реестр
2. **Оценка:** Определить вероятность и влияние
3. **Планирование:** Выбрать стратегию и разработать план
4. **Мониторинг:** Еженедельно проверять триггеры
5. **Реагирование:** При срабатывании триггера — активировать план
